## 기준

기존 AppTheme의 의미별 색상과 대비 계산, PlanBaseButtonStyle을 확장해 사용한다.
주요 행동은 강조, 보조 행동은 낮은 강조, 삭제는 파괴적 역할을 사용한다. 같은 취소 동작의 문구는 통일한다.
편집 초안은 변경 전 snapshot과 비교하고, 변경 시 닫기/취소가 조용히 내용을 버리지 않게 한다.
읽기 화면은 닫기, 명시 저장 화면은 취소/저장, 자동 저장은 저장 상태 피드백을 제공한다.
일정은 사용자 문구에서 일관된 용어를 사용하되 내부 모델·호환 이름은 유지한다.
모바일의 터치 영역과 Mac의 키보드·포인터 조작은 플랫폼에 맞게 적용한다.

참고: [Apple Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons),
[Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts),
[Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets),
[Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility/).

## 평가

현재 점수는 확인하지 못한 항목을 통과로 간주하지 않는 보수적 평가다. 실제 VoiceOver·잠금 privacy, 설정에서 권한 변경 후 앱 복귀, Mac/Watch 연속 조작은 해당 영역에서 감점했다.

| 영역 | 배점 | 변경 전 | 현재 | 판단 근거 |
|---|---:|---:|---:|---|
| 디자인 일관성 | 30 | 17 | 29 | 공통 버튼·안내·폐기 확인·오류 복구·한국어 용어·삭제 영향 문구를 플랫폼 간 통일. Mac 네 탭·테마·메모 실제 화면도 확인했으며 Watch 연속 조작과 D70 수정 후 Mac 화면 1점 감점 |
| 정보 위계·가독성 | 20 | 12 | 19 | 기록 읽기 상세, 긴 날짜·이력·작업명, 오류와 빈 상태, 큰 글자 시 세로 재배치, Mac 기본 화면을 실제 확인. 일부 Watch·D70 수정 후 Mac 화면 1점 감점 |

## 검증 계획과 현재 결과

- 격리된 변경 전 소스 310파일을 baseline-manifest와 해시 대조해 보존. iPhone/Mac baseline 빌드 통과. iPhone 원본 8개 시나리오 중 7개 통과, 최근 일정 추천 경로 실패. 실패 수집 진단은 600초 timeout으로 종료되었으며 테스트 결과와 구분한다.
- iteration1 공통 테스트 exit 0(399개 중 3개 선택적 skip). iPhone 관련 6개 시나리오 중 5개 통과, 일정 복제 완료 안내 실패. 45분 집중 연결·초안 보호 스크린샷을 확인했다.
- iteration2 iOS build-for-testing와 수정 Mac Debug build 통과. 새 체크리스트·템플릿·기간 접근성 시나리오와 일정 복제/회고 피드백 재검증 진행 중. 테스트는 --ui-testing 메모리 컨테이너를 사용한다.
- iteration2: 일정 추천/복제 결과와 완료 안내, 회고 저장, 마지막 체크리스트 입력 저장 통과. 최대 글자 크기 일정 편집은 키보드가 가린 스크롤 조작에서 실패했다. 템플릿 테스트에는 빈 저장소에 적용할 템플릿이 없었다.
- iteration3: 편집 필드 포커스와 키보드 도구를 정리한 뒤 일정 AX5 프리셋/12일 직접 입력/저장 및 회고 저장 통과. 템플릿 테스트는 실제 템플릿 생성까지 포함하도록 바꿨고, 이후 드러난 템플릿 키보드 가림을 수정했다.
- iteration4: iOS build-for-testing 통과. 템플릿 생성 → 초안 수정 → 닫기/계속 작성 → 재로드 취소/확인 → 다른 템플릿 적용 후 초안 유지 → 저장 → 경고 없이 닫기 전 과정 통과(31.437초).
- Mac 수정 앱: 작업 제목 수정 → Escape 확인 → 계속 작성 → 저장 후 보드 반영 확인. 템플릿 이름 초안의 Escape 확인, 다른 템플릿 3개 작업 적용 후 이름/초안 유지, 템플릿 저장 확인. 일정 편집 삭제 확인 후 삭제 실행 및 달력 숨겨진 일정 3개→2개 감소 확인. 각 단계 JSON/스크린샷은 `after-Mac/`에 보존했다.
- Mac 텍스트 필드의 AXSetValue는 비포커스 항목의 표시값만 바꾸고 SwiftUI 모델에는 반영되지 않는 경우가 있었다. 포커스된 필드의 편집과 저장 결과를 함께 확인한 경로만 동작 검증에 포함했다. 템플릿 원본의 비포커스 AX 쓰기 자료는 코드에서 확인한 초안 손실의 보조 자료이며 독립적인 동작 증거로 집계하지 않는다.
- iPad 변경 전/후 가로·세로와 기록 AX5, 좁은 창의 저장 작업 편집, 주요 모달의 키보드·큰 글자를 실제 확인했다. 기록의 큰 글자는 세로 스크롤로 이어지며 창 밖 가로 넘침은 없다. 메모 텍스트·체크리스트·필기와 활동 이모지 편집은 iteration275~281에서 iPad 실제 조작까지 추가 확인했다.
- iPad 가로·세로/좁은 창, Watch 40mm와 11테마·시스템 위젯 표시, 동작 줄이기는 확인했다. Mac 최신 창 크기·키보드/포인터, Watch 버튼 연속 조작, 실제 VoiceOver와 보안 잠금 privacy는 도구·환경 제약으로 남아 있다.
- 최신 전체 플랫폼 회귀 iteration424가 통과했다. D69 메모 시각과 D70 일정 기간 공통 한국어 표기를 포함하며, 공통 Debug 407개·Release 405개와 iOS/macOS Debug·Release, 포함 Watch/위젯 번들·privacy manifest를 확인했다.
- D65의 한국어 날짜 기준과 일정 복제 저장 실패 복구는 iPhone338·iPad339에서 통과했고, 프로젝트 기본 언어와 모바일·Mac·Watch 루트 로케일 변경은 전체 회귀340에서도 통과했다.
- 초기 Goal 범위 밖이었던 TestFlight 배포는 사용자 후속 요청으로 build 71에 반영했다.

- iteration5: iOS 빌드 통과. 기록 목록과 하루 기록 두 회고 저장 경로(22.597초), 보드 회고 저장(17.596초) 통과. 두 기록 경로의 완료 안내 스크린샷을 확인했다. 템플릿은 즐겨찾기 필터에서 초안 유지까지 통과 후, 목록 밖 가상화된 필드를 조회하는 테스트 실패였다. 입력칸을 다시 스크롤해 확인하도록 수정했다.
- iteration6: iOS 빌드 통과. 복구 AX5/재시도, 동기화·필터 Charcoal Rose AX5 통과. 템플릿 배치와 날짜 선택 취소 보호 테스트는 실행 중이다.
- 격리된 새 Watch SE 3 40mm 시뮬레이터를 만들었다. 변경 전 Watch 앱의 서명에 iCloud entitlement가 없음을 확인했고 로컬 저장소로만 실행한다. 실제 Watch 사용자 데이터나 CloudKit 레코드는 사용하지 않는다.

- D14 Watch 40mm에서 수정 전 녹색 체크와 오류 문구가 함께 표시되는 것을 재현했다. 수정 후 동일한 로컬 권한 오류에서 주황색 경고 아이콘/문구로 표시되는 것을 캡처해 확인했다. `watch-before-empty.png`, `watch-after-error.png`에 비교 자료가 있다. 사용자 계정·CloudKit 대신 새 시뮬레이터에서 unsigned 앱을 사용했다.
- Watch Debug 전용 `--ui-testing`은 메모리 저장소와 seed를 사용하며 기존 코어의 프로세스별 집중 타이머 테스트 폴더와 함께 격리된다. Release 경로는 바꾸지 않았다.
- Orca Simulator 접근성 읽기가 2회 실패했다. computer-use 스킬 안내대로 권한 확인/헬퍼 재기동을 수행했고 권한은 granted지만 동일 오류가 반복됐다. simctl 화면 캡처는 가능하다. Watch 직접 조작과 키보드 검증은 이 오류가 해소되기 전까지 미검증이며 전체 Goal 완료로 집계하지 않는다.
- AX5 스크린샷에서 segmented 선택지만 작은 글자로 남는 문제(D15)를 확인했다. 공통 `PlanBaseAdaptiveSegmentedPicker`로 접근성 크기에서 메뉴 선택으로 전환하고 작업 상태·템플릿·보관함·필터·메모 방식·테마/활동 표현에 연결했다. 집중 작업 선택 sheet에도 글자 크기를 명시 전달했다. 이후 iPhone AX5 필터/상태 선택과 iPad 메모의 펼쳐진 세그먼트 선택을 iteration280까지 확인했다.
- iteration7 템플릿 테스트 로그에 새 스크롤 보조 함수의 동작이 나타나지 않아 빌드와 설치된 테스트 runner의 일치 여부를 확인 중이다. 이전 실패를 제품 동작 실패나 통과로 임의 분류하지 않는다.

- iteration7 runner 조사 결과: 빌드 산출물과 설치된 테스트 실행 파일의 SHA-256이 같고 새 보조 함수도 포함됐다. 따라서 오래된 runner라고 단정하지 않는다. 탐색 동작을 명확하게 하기 위해 템플릿 검색으로 후보를 좁힌 뒤 동일 템플릿/필터/다른 템플릿 전환과 날짜 선택을 끝까지 검증하는 시나리오로 정리했다.
