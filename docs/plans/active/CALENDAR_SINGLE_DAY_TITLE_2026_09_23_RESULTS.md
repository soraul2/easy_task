# 단일 날짜 일정 제목 두 줄 표시

사용자의 2026-09-23 진행 요청에 따른 후속 변경이다. 이전 UI·UX Goal의 검증된 작업 트리를 보존하고 이어서 수정했다. 커밋·푸시·배포는 포함하지 않는다.

## 표시 규칙

- 실제 시작일과 종료일이 같은 일정에서 제목이 현재 글꼴·날짜 칸 너비에 들어가지 않을 때 최대 두 줄을 사용한다.
- 짧은 제목과 여러 날짜 일정은 한 줄이다. 주·월 경계에서 한 칸만 보이는 다일 일정도 한 줄을 유지한다.
- 날짜 칸 높이는 유지한다. 같은 글자 크기의 한 줄 배치에서 보이는 일정 집합과 다일 일정 위치를 먼저 확정하고, 남는 공간에만 긴 하루 제목을 확장한다. 숨겨진 일정이 있는 날은 확장하지 않는다.
- iPhone·iPad는 글자 크기에 맞춰 일정 행 높이를 계산한다. 공간이 부족하면 개수 표시와 날짜 상세로 이어진다. 접근성 글자 크기에서 사용하던 그래픽 막대와 전체 날짜 상세는 유지한다.
- 숨겨진 일정 개수는 날짜 헤더에 표시하여 일정 막대와 겹치지 않게 한다. 접근성 크기의 좁은 칸에서는 기존 하단 배지를 사용하고, 가로 화면처럼 넓은 칸에서는 헤더에 표시한다. iPhone의 큰 글자에서 두 자리 날짜가 말줄임되는 문제도 수정했다.
- 월 전체가 화면 높이를 넘는 경우 세로로 스크롤하여 마지막 주를 열 수 있다. 하단 탭을 피할 수 있도록 스크롤 여유를 둔다.
- 위젯은 확장을 요청하지 않으므로 기존 한 줄 배치를 유지한다. 제목·날짜·저장 데이터는 변경하지 않는다.

## 구현

`CalendarEventGridLayout`에 선택적 확장 요청과 세로 점유 행 수를 추가했다. 기존 단일 행 결과에서 단일 날짜 일정만 빈 행에 다시 배치하며, 확장 후에도 일정 사이의 공간과 표시 개수를 보존한다. iOS와 Mac이 같은 배치 규칙을 사용한다.

`CalendarEventTitleMetrics`는 실제 표시와 동일한 semibold 글꼴로 제목 너비를 측정한다. UI는 결과의 높이에 맞춰 최대 두 줄을 그린다. 문자열 길이를 글자 수로 추측하거나 다일 일정의 표시 폭으로 기간을 판정하지 않는다.

데이터 스키마·호환 식별자·저장/rollback·CloudKit·백업 및 bounded query는 변경하지 않았다. 추가한 공통 파일은 Swift Package에서 자동 발견된다.

## 검증

증거 루트: `.local/calendar-wrap-20260923/`. UI 검사 원본은 기존 전용 Simulator 실행 도구의 `.local/uiux-20260922/calendar-wrap*/`에 저장한다.

- 공통 캘린더 관련 검사 36개 통과. 신규 4개 검사는 용량별 표시 집합 보존, 행 충돌 방지, 주·월 경계, 다일 위치 보존, overflow와 위젯 기본 배치를 확인한다.
- 공통 API 변경에 따른 전체 플랫폼 회귀 게이트 통과: Debug 공통 검사 501개, Release 498개, iOS·macOS·watchOS Debug/Release 및 내장 번들 검사. `gate-status.json`에 실행 시점 해시와 exit code를 기록했다.
- 게이트 실행 중 캘린더 UI와 UI 검사 4개 파일을 추가 수정했으므로, 전체 게이트가 최종 작업 트리를 그대로 검사했다고 해석하지 않는다. 공통 코어·위젯·Watch는 이후 변경되지 않았다. 최종 iOS/Mac 빌드와 UI 검사를 별도로 연결한다.
- Mac 최종 캘린더 소스의 Debug/Release 빌드 통과. 실제 화면 검사는 아래 잠금 경계로 보류한다.
- 최종 iOS Debug 검사 빌드와 Release 빌드 통과 (`ios-final-release-status.json`, exit 0, sourceUnchanged=true). 빌드 시점과 최종 소스 해시가 동일하다. iPhone 일반/xxxLarge/AX5 세로·가로 및 전체 제목을 보여 주는 날짜 상세 검사 통과 (`calendar-wrap-complete-phone`, 실패 0).
- AX5 가로에서 실제로 스크롤한 뒤 30일 칸 전체가 하단 탭 위에 표시되고, 탭하여 날짜 상세를 여는 것까지 통과했다. 최종 접근성 프레임은 날짜 칸 y=252…306, 탭 시작 y=326이다. 앞선 실패 실행에서는 기본 스와이프 시작점이 하단 탭에 가려져 월 영역을 스크롤하지 못했다. 월의 노출된 영역에서 드래그하도록 검사를 수정했고, 화면 캡처와 실제 날짜 탭을 함께 확인했다.
- 실제 iPad 창을 1180×820에서 585×820으로 줄인 검사 통과 (`calendar-wrap-complete-ipad`, 실패 0). 긴 제목/짧은 제목 높이 차이와 숨겨진 6번째 일정에 도달하는 경로를 확인했다. 잘못된 iPhone 대상으로 실행하여 skip된 초기 실행은 iPad 통과 근거에서 제외했다.
- 기존 일정 편집 후 다시 열어 변경이 유지되는 회귀 검사도 통과했다 (`calendar-wrap-phone`).
- 최종 원본 결과, 빌드 해시 대조, Mac 보류와 실행 경계는 `.local/calendar-wrap-20260923/final-verification.json`에 정리했다.

## Mac 검증 실행 경계

초기 하위 프로세스가 종료된 뒤 화면 도구가 앱을 테스트 인수 없이 다시 실행했다. fixture가 아닌 화면을 발견하여 즉시 종료했다. 인수 없는 실행은 일반 로컬 저장소 경로로 진입하므로 그 저장소에 변경이 없었다고 단정하지 않는다. 해당 실행은 검증에서 제외하며 직접 저장소를 조사하거나 수정하지 않았다. 앱의 CloudKit entitlement는 제거된 상태였다.

이후 `--ui-testing --ui-testing-discovery-fixtures --ui-testing-calendar-wrapping` 인수가 적용된 프로세스를 확인했다. 실제 화면 검증을 시도할 때 Mac이 잠겨 있어 사용자의 잠금 해제를 요청했다. 실제 Mac 화면 통과 여부는 빌드 성공과 구분한다.

검증용 Mac 앱은 종료했다. 최종 Mac 소스와 일치하는 별도 검증 앱 `PlanBaseCalendarFinal.app`은 준비되어 있으나 아직 실행하지 않았다. 잠금 해제 후 위 인수로 실행하고 실제 프로세스의 인수를 먼저 확인한 뒤 화면 도구를 연결해야 한다. 최소/넓은 창의 두 줄 표시와 일정 편집 진입 확인이 남아 있다.

전용 Simulator 세 대는 검증 후 모두 종료했다. 이번 후속 변경에서는 커밋·푸시·TestFlight 업로드를 수행하지 않았다.

## 후속 배포

2026-09-23 별도 배포 요청으로 변경사항을 `2462a3d`에 커밋·푸시하고 iOS·macOS TestFlight 1.0(82) 업로드를 완료했다. 위의 미커밋·미배포 표현은 구현·검증 당시 범위를 설명한다. Apple 처리 및 남은 확인 범위는 [빌드82 배포 기록](../../releases/TESTFLIGHT_BUILD_82.md)을 따른다.
