## 발견 사항 (검증에 따라 갱신)

- P0 위험: 메모 필기/체크리스트 조회 오류를 빈 데이터로 취급해 기존 내용을 덮을 수 있었다. 읽기 성공 전 편집/저장을 차단하고 재시도를 연결했다. 공통 오류 주입 및 iPhone 화면 테스트 통과.
- P1: 메모 저장 실패 후 Mac의 다른 메모 선택/iPhone의 뒤로 가기에서 미저장 세션을 버릴 수 있었다. 저장 결과를 확인하고 실패 시 초안을 유지한다. 고정 성공이 저장 실패 표시를 덮던 문제도 수정했다.
- P1: Mac 루틴 생성 후 복제 편집기가 빈 이전 상태를 재사용했다. 편집 요청별 identity를 지정해 복제 내용을 초기화한다. Mac 재현 전후 화면과 iPhone/iPad 관련 검사 각 3개 통과.
- P2: 메모 등 무관한 변경에도 작업 알림·Live Activity·위젯·진행/기록 조회를 요청했다. 저장 알림에 변경 영역을 포함하고 소비처에서 필요한 영역만 갱신한다. 영역 정보가 없는 백업/import 알림은 전체 갱신한다. 선행 편집 저장과 실패 rollback을 공통 테스트로 확인했다.
- P2: 메모 갱신 시 이미 펼친 페이지가 첫 페이지로 돌아가고 대기 중인 검색어를 무시했다. 페이지 깊이/실패 시 기존 행을 유지하고 최신 검색을 적용한다. iOS 경로도 선택한 메모를 유지해 목록 갱신에 따라 새 메모로 오인하지 않게 했다.
- P2: 동일 체크리스트를 대입하는 `inout` helper가 SwiftData setter를 호출해 불필요한 변경을 만들었다. 재현 실패 로그 `baseline/memo-checklist-writeback.log`; 실제 다른 값만 대입하도록 수정 후 통과.
- P2: 긴 메모 제목/미리보기가 매번 전체 텍스트를 분할했다. 필요한 줄까지만 계산하고 미리보기는 240자와 생략 표시로 제한한다. 편집/검색 원문은 유지한다.
- P2: 하루 기록에서 작업마다 조회 구간 전체 날짜를 반복 계산했다. 실제 시작/닫힌 진행 구간이 있는 날짜만 집계하도록 수정했다. 미국·한국·호주·UTC의 날짜 경계와 23/25시간 날짜를 포함해 기존 일별 계산과 비교했다.

- P1 위험: Mac 필기 미리보기가 영역 크기에 비례한 이미지를 body에서 반복 생성했다. 데이터가 바뀔 때만 만들며 긴 변 1,800px 상한을 적용했다. 원본을 변경하지 않고 순수 크기 계산 테스트를 통과했다.
