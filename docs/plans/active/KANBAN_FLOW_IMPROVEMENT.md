# 칸반 입력 → 진행 → 완료 흐름 개선

2026-09-08. 칸반 시나리오 점검에서 확인한 표시 오류와 상태 이동·실수 복구·시간 의미를 개선한다.

## 적용 범위

- 공통 진행 표시: 미완료 작업의 닫힌 구간은 `진행 중단`, 완료 작업은 `완료`로 표시한다. 진행 중·중단·완료 모두 `진행 누적`으로 통일한다. 시작 시각이 없는 진행 상태는 기록이 없다고 표시하며 시간을 합성하지 않는다.
- iPhone·iPad: 상태 변경 알림에 `할 일 보기` / `진행 중 보기` / `완료 보기`를 제공한다. 버튼을 누르면 현재 저장된 작업의 상태와 날짜를 다시 조회해 필터를 변경하고 해당 카드로 이동·강조한다. 다른 날짜 작업을 오늘 완료한 경우에도 오늘 완료 보드로 이동한다.
- macOS·iPhone·iPad 보드: 단일 완료 직후 15초 동안 `완료 실행 취소`를 제공한다. 가장 최근 보드 완료에 대한 동작이며 다른 상태 변경·안내나 화면 이탈로 닫힐 수 있다. 상세 편집·일괄 완료·집중 모드·Watch 완료에는 이번 동작을 추가하지 않는다.
- 기록의 하루 활동 목록: 완료 증거가 있는 작업의 현재 상태가 미완료이면 `현재 진행 중 · 완료 이력 유지` 또는 `현재 할 일 · 완료 이력 유지`를 보조 표시한다. 작업이 삭제된 경우에는 현재 상태를 추정하지 않는다.
- Mac 집중 진입은 `집중 시작`으로 표현한다. 보드의 접근성 설명과 Mac 도움말은 진행 누적이 진행 상태로 둔 시간이며 집중 타이머와 다르다는 점을 알린다.

## 완료 실행 취소의 저장 경계

`TaskCompletionUndoService`는 기존 `TaskLifecycleService.applyStatus`를 호출해 완료를 즉시 저장한다. 반환한 기기 로컬 영수증은 완료 전 상태·순서·진행 및 완료 레코드의 물리 식별자와 버전을 담는다. 영수증 자체는 저장·동기화하지 않는다.

취소할 때는 한 번의 `PersistenceCommandService.perform` 안에서 다음을 확인하고 반영한다.

1. 유효 시간 안이고 활성 Task 후보가 하나이며, 같은 물리 Task의 완료 상태·완료 시각·계획일·보관 정보·순서·갱신 시각이 일치해야 한다.
2. 관련 날짜의 완료 기록과 해당 Task의 진행 기록이 완료 직후 버전과 동일해야 한다. 편집, 삭제, 중복 수렴, 추가 import가 감지되면 전체 취소를 거부한다.
3. 이번 완료에서 새로 만든 완료 활동과 진행 종료 이벤트만 `supersededAt`으로 비활성화하고 `updatedAt`을 갱신한다. 물리 레코드를 즉시 삭제하지 않는다.
4. 이전 Task 상태와 순서·완료·보관 필드를 복구한다. 원래 진행 중이었던 작업은 이번 종료 이벤트만 제외되어 원래 시작 구간이 이어진다. 재시작 이벤트를 새로 만들지 않는다.
5. 같은 날이나 이전 날짜에 이미 존재한 완료 이력, 체크리스트, 알림 설정, 집중 세션은 보존한다. `다시 진행`은 기존 수명주기를 사용하며 완료 이력을 보존한다.
6. 뒤늦게 들어오는 같은 완료 시각의 legacy 완료 활동과 같은 종료 시각의 compatibility 진행 경계는 비활성화된 captured 기록을 확인해 다시 표시되지 않게 정리한다. 다른 시각의 이전 완료·진행 기록은 유지한다.
7. 저장 실패는 Task와 두 기록 종류 모두 rollback한다. iOS 알림과 위젯은 기존 저장 성공 알림에 따라 재계산된다. 미래 알림만 다시 예약 대상이 된다.

SwiftData V11, CloudKit 스키마, 백업 형식은 변경하지 않는다. 취소 후 새 백업은 현재 활성 기록만 포함하며, 새 저장소에 복원해도 취소된 완료가 생기지 않아야 한다. 기존 백업 병합은 삭제 동기화가 아닌 기록 복원이므로 **취소 전 백업을 명시적으로 병합하면 과거 완료가 다시 들어올 수 있다**. 이를 영구 삭제/취소 이력 기능으로 취급하지 않는다. 지연 legacy backfill과 compatibility boundary import는 메모리 저장소에서 검증한다. 실기기 CloudKit의 실제 전송·동시 변경은 출시 전 별도 검증 대상이다.

집중 타이머 자체를 되감거나 이미 전달된 시스템 알림을 복원하지 않는다. 이 동작은 보드에서 잘못 누른 단일 완료의 정정이다.

## 검증

검증 로그·UI 결과·화면 자료는 `.local/kanban-flow-improvements/`에 보관한다.

- 공통 테스트: 할 일/진행 중 완료 취소, 원래 시작 구간·알림·순서 복구, 같은 날/이전 날짜 이력 보존, 취소 후 재완료, 만료·편집·재진행·삭제·중복·기록 import 거부, 실패 rollback, 새 context 읽기와 백업 왕복.
- 표시 테스트: 중단/완료 구분, 반복 진행 누적, 0초 진행 구간, 시작 시각 누락, 현재 상태와 과거 완료 증거의 구분.
- 모바일 UI 테스트: 상태 목적지 이동, 완료 실행 취소, 다른 날짜 완료의 오늘 이동과 원래 날짜 복구, 일반 재진행 후 완료 이력 보존.
- 기존 체크리스트·미래 알림 완료·집중 흐름·스크롤 중 상태 오조작 방지 회귀.
- 전체 플랫폼 Debug/Release 패키지 테스트와 앱·내장 위젯·Watch 빌드 검증.
