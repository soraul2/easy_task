# PlanBase UI·UX 개선 Goal 실행 프롬프트

PlanBase의 UI·UX를 실제 화면과 사용자 흐름을 기준으로 개선해 줘. Goal 도구에 아래 목표를 등록하고 조사·구현·검증·결과 문서 작성까지 진행해 줘.

목표: ‘PlanBase에서 주요 기능을 쉽게 찾고, 큰 글자·좁은 화면·키보드 환경에서도 제목과 조작이 가려지지 않으며, 작성 중인 내용과 선택 상태가 유지되도록 개선한다. 확인된 문제를 재현하고 수정한 뒤 iPhone·iPad·macOS의 관련 흐름과 공통 UI 영향을 검증한다.’

별도 숫자 토큰 예산은 지정하지 않는다. 유의미한 개선과 검증 근거를 충분히 확보한다. 이미 해결된 항목은 현재 코드·실행 결과를 확인한 뒤 유지한다.

## 1. 시작과 기준 확정

1. `AGENTS.md`, `git status --short`와 현재 HEAD를 확인하고 기존 사용자 변경을 보존한다.
2. 다음 문서를 읽는다.
   - `docs/plans/active/UI_UX_2026_09_22_AUDIT.md`
   - `docs/plans/active/UI_DESIGN_CONSISTENCY.md`의 관련 항목
   - `docs/plans/active/UI_DESIGN_SURFACE_INVENTORY.md`의 관련 화면
   - `docs/plans/active/OPTIMIZATION_2026_09_22_RESULTS.md`
   - `docs/releases/TESTFLIGHT_BUILD_81.md`
3. 과거 디자인 기록은 build 70/71, 이번 점검은 build 81 기준이다. 실행을 시작할 때 현재 소스와 비교하여 이미 해결됐거나 바뀐 항목을 갱신한다.
4. `.local/uiux-<실행일>/` 아래에 환경·기준 소스 해시·수정 전 화면·문제별 재현 경로를 보존한다. 관련 화면과 소스 변경만 복사하며 사용자 데이터는 수집하지 않는다.
5. 조사 결과를 `확인된 결함`, `사용 편의 개선`, `검증 필요`, `유지`로 나누고, P1/P2·영향 플랫폼·수정 파일·완료 기준을 기록한다.

## 2. 우선 개선 항목

우선 U01·U02와 U09의 실제 결함 분류를 진행하고, 이어 U03~U07을 개선한다. U08은 안내 영역 조사에 포함한다. 재현되지 않거나 이미 해결된 항목은 최신 근거로 유지 결정한다.

### U01. 큰 글자 기록 제목과 상단 구조

- iPhone에서 기록 → 활동 기록/회고를 일반·확대·최대 접근성 글자로 각각 확인한다. 검색 진입 전후, 필터, 목록↔상세, 가로 전환도 포함한다.
- `MobileArchiveView`, `MobileReviewDiscoveryView`의 큰 navigation title과 toolbar·검색·pane 선택 영역의 관계를 조사한다.
- 제목 잘림·겹침을 고치고 중요한 필터·작성·뒤로 행동을 유지한다. 시스템 글자 크기를 강제로 줄여 문제를 숨기지 않는다.
- 완료 기준: ‘기록’과 현재 화면 맥락을 읽을 수 있고 검색·필터·작성·뒤로 이동이 가능하다. pane/탭 복귀 때 검색어·선택·스크롤이 보존된다. 두 pane의 전후 화면과 조작 근거가 있다.

### U02. 결과 안내와 완료 취소

- 최대 글자에서 칸반 완료 안내가 차지하는 면적과 뒤쪽 작업 조작을 측정한다. 안내를 읽고 완료 보기·실행 취소·다음 작업 편집을 실제 수행한다.
- 긴 작업 제목을 포함한 결과 문구와 행동의 우선순위를 정리한다. 적응형 배치나 본문 공간 확보 등을 비교해 읽기와 연속 조작을 함께 만족하는 방식을 선택한다.
- `MobileSavedNoticeModifier`와 `CalendarNoticeBanner`도 저장 직후 터치·스크롤을 막는지 재현한다. 재현되지 않으면 근거와 함께 유지한다.
- 완료 취소의 15초 유효기간, 작업 상태·완료 활동·알림의 의미, 안내의 접근성 전달, 칸반 수동 행동 없는 안내의 터치 통과를 보존한다.
- 완료 기준: 안내 때문에 필요한 행동이 숨겨지거나 막히지 않는다. 긴 제목·최대 글자·연속 두 번 조작·탭 전환·키보드 조건에서 안내 대상이 뒤섞이지 않고 기존 실행 취소 검사가 통과한다.

### U03. 주요 탭의 의미 전달

- iOS/iPadOS의 아이콘 전용 tabItem과 macOS `FloatingTabBar`에 짧은 가시적 이름을 제공하는 방안을 검토하고 가장 명확한 배치를 구현한다.
- 칸반·캘린더·기록·메모의 기존 구조와 선택 상태, Mac 단축키·도움말·접근성 이름을 유지한다.
- 완료 기준: 처음 보는 사용자도 탭의 목적을 화면에서 읽을 수 있다. 좁은 화면에서 이름이 충돌하지 않고 하단/상단 콘텐츠·집중 실행 버튼을 가리지 않는다.

### U04. 메모 빈 화면과 검색 실패 후 다음 행동

- 빈 메모 화면에 ‘새 메모’ 행동을 배치하고 기존 텍스트·체크리스트·필기 종류 선택 흐름으로 연결한다.
- 검색 결과 없음에는 검색어 지우기 등 바로 실행할 복구 행동을 제공한다. 초기 조회 실패와 빈 상태를 구별한다.
- 완료 기준: 빈 화면에서 작성 흐름에 바로 진입하고, 종류 선택 취소·내용 없는 편집기 닫기는 빈 레코드를 남기지 않는다. 검색 초기화와 저장 실패 재시도에서 초안·기존 메모가 보존된다.

### U05. 템플릿·루틴·저장한 작업 용어

- 같은 개념에 사용되는 화면 제목·진입 버튼·검색·작성·삭제 문구를 표로 정리하고 대표 용어를 일관되게 사용한다. 필요한 곳에 작업 묶음과 개별 작업의 관계를 짧게 설명한다.
- 한 항목 루틴과 저장한 작업은 같은 레코드를 사용하는 기존 의미를 유지한다. 편집·삭제가 양쪽에 반영되는 결과를 해당 행동 가까이에서 이해할 수 있게 한다.
- 완료 기준: 생성→저장→검색→재사용→편집→삭제에서 같은 개념의 이름이 일관된다. 이미 보드에 추가된 작업 보존, 중복 적용 선택, 입력어·즐겨찾기 동작이 유지된다. 내부 모델·식별자 이름은 UI 문구 변경과 별개로 유지한다.

### U06. 큰 글자 목록의 정보량

- 회고 목록과 템플릿 목록에서 긴 제목·긴 본문·여러 사진·다수 작업을 넣고 다음 항목을 찾기까지 필요한 스크롤과 행동을 기록한다.
- 목록에는 제목·날짜/개수·간결한 미리보기를 배치하고, 전체 본문은 명시적인 전체 읽기/펼치기로 접근하도록 정보 구조를 정리한다. 중요 내용과 행동을 단순히 잘라 없애지 않는다.
- 완료 기준: 같은 fixture에서 탐색 부담을 줄인 근거가 있고 전체 내용·사진·수정·적용 기능에 접근 가능하다. VoiceOver 레이블과 목록↔상세 복귀 위치도 보존한다. 개선 효과가 없는 변경은 채택하지 않는다.

### U07. macOS 키보드·접근성 정렬

- macOS 작업 상세 체크리스트를 마우스 없이 추가·수정·완료·순서 변경·저장·재열기한다. 현재 드래그 정렬에 시스템이 제공하는 실제 접근성 경로도 확인한다.
- 접근 가능한 경로가 부족하면 위/아래 이동 메뉴·버튼·접근성 행동을 추가하고 드래그도 유지한다. 기존 저장·순서 규칙을 재사용한다.
- 완료 기준: 첫/중간/마지막 항목 정렬과 저장 후 재열기가 올바르며, 취소·저장 실패에서도 원본/초안 규칙이 유지된다. 키보드 포커스가 이동한 항목을 따라가고 사용 가능한 행동을 이해할 수 있다.

### U09. 새 접근성 감사 지적의 분류와 해결

- `.local/uiux-audit-20260922/attachments/manifest.json`과 네 화면의 `accessibility-findings` 원본을 읽는다. 54건은 원본 지적 수이며 제품 결함 수가 아니다.
- 칸반 10·캘린더 40·기록 3·메모 1건을 같은 조건에서 재현한다. 대비 44·터치 영역 2·확대 시 잘림 가능성 8건을 중복/실제 결함/시스템 요소/의도된 요약으로 분류한다.
- 대비는 실제 글자·배경·테마·선택 상태로 검증하고, 작게 잡힌 영역은 표시 전용 텍스트와 실제 버튼을 구별한다. 캘린더 요약은 날짜 상세와 접근성 전체 이름까지 확인한다.
- 확인된 결함에만 공통 색상 토큰·접근성 묶음·레이아웃 수정을 적용한다. 색상 변경은 영향을 받는 테마와 상태를 함께 검증한다.
- 완료 기준: 모든 원본 지적에 분류·근거·조치 또는 유지 이유가 연결된다. 수정한 실제 결함은 재검사하고 남은 자동 지적을 설명한다. 단순히 예외 처리해 지적 숫자만 줄이지 않는다.

## 3. 화면·접근성·상태 보존 원칙

- 현재 PlanBase의 테마·분위기를 유지하면서 정보 순서, 읽기, 조작을 개선한다. 새 기능과 장식 추가는 위 문제 해결에 필요한 범위로 제한한다.
- 기존 `PlanBaseButtonStyle`, `PlanBaseControlMetrics`, `AppTheme`, 적응형 picker·split view 패턴을 먼저 활용한다. 공통 규칙을 플랫폼 UI에 복제하지 않는다.
- iPhone/iPad 주요 터치 행동은 44×44pt 이상을 기본으로 확인한다. macOS·Watch는 해당 플랫폼의 기존 구성과 입력 방식에 맞춰 평가한다.
- 색만으로 상태를 전달하지 않고 레이블·아이콘·선택 상태를 함께 확인한다. 큰 글자, 대비 증가, 동작 줄이기에서 필수 내용과 행동을 보존한다.
- 탭·회전·창 폭 변화·테마 변경·백그라운드 복귀 시 검색어, 날짜, 선택, 스크롤, 편집 초안, 체크리스트, 집중 타이머가 보존되는지 변경 영향 범위에서 검증한다.
- 전체 데이터 관찰·원본 이미지 즉시 decode·고빈도 전체 재계산을 추가하지 않고 기존 bounded query와 최근 성능 개선을 보존한다.

## 4. 데이터와 호환성 경계

- 실제 사용자 데이터 대신 메모리/격리 로컬 fixture와 전용 Simulator·진단 앱을 사용한다. 앱 실행 전에 저장소·preferences·App Group·동기화 격리를 확인한다.
- `/Users/home/Library/Mobile Documents`와 그 하위 iCloud Drive 경로는 읽기·탐색·수정하지 않는다. `.local/backups/`와 실제 사용자 저장소를 건드리지 않는다.
- 배포된 V1~V11 스키마, `EasyTaskCore`, bundle ID·CloudKit container·App Group·백업 형식과 레거시 경로를 유지한다.
- `PersistenceCommandService`의 save/rollback, 논리/물리 ID와 중복 수렴, Task 진행·완료 기록·알림의 원자성을 보존한다. 이번 UI·UX 범위에서 스키마 변경은 하지 않는다.
- 새 플랫폼 소스가 필요하면 Xcode 타겟 membership을 등록한다.

## 5. 검증과 완료 판정

1. 각 문제는 재현→수정→동일 조건 재검증으로 진행한다. 전후 화면은 같은 기기·크기·테마·fixture·스크롤 조건을 사용한다.
2. 필수 로컬 범위는 iPhone 일반/확대/최대 글자·세로/가로, iPad 세로/가로/좁은 창, macOS 최소/넓은 창과 키보드 흐름이다. 모든 조합을 반복하는 대신 변경된 화면의 실패 가능 조건을 우선한다.
3. 공통 UI 변경은 11개 테마의 대표 화면을 대조하고 이상 조합을 상세 검사한다. Focus·Widget·Watch에 영향이 있으면 해당 화면·행동의 회귀도 수행한다.
4. 현재 접근성 자동 감사는 지적을 수집하는 검사이며 성공이 문제 0건을 뜻하지 않는다. 원본 지적을 보존하고 실제 결함·시스템 요소·의도된 요약·중복을 분류한다. 확인된 결함에는 의미 있는 회귀 검사를 둔다. 무조건 무시 처리로 통과시키지 않는다.
5. 수정 범위의 관련 검사부터 실행한다. 공통 API·Xcode 설정·공통 UI 영향이 넓으면 `./scripts/verify-platform-builds.sh`까지 통과시킨다. 빌드 성공만으로 UI 품질이 검증됐다고 하지 않는다.
6. `SDKROOT`가 CommandLineTools의 다른 SDK를 가리키면 해당 검사 실행에서만 제거하고 Xcode와 맞는 SDK를 사용한다. 시스템 설정을 임의로 바꾸지 않는다.
7. 실기기 VoiceOver 발화·Pencil·Watch 햅틱·잠금/Always-On·CloudKit 왕복은 이 Goal의 로컬 완료 판정과 분리해 미검증 인수 항목으로 명시한다. 도구로 확인하지 못한 결과를 통과로 표기하지 않는다.
8. 최종 소스와 검증 대상 소스가 일치하는지 확인하고, 사용한 전용 테스트 앱/Simulator만 정리한다. 증거와 백업은 보존한다.

산출물은 `UI_UX_2026_09_22_PLAN.md`, `UI_UX_2026_09_22_RESULTS.md`, 검증된 코드 변경과 전후 화면·검사 로그다. 최종 보고에는 채택한 개선, 유지한 부분과 이유, 시나리오별 결과, 남은 인수 항목을 담는다.

Goal은 위 필수 로컬 항목의 수정·검증 또는 근거 있는 유지 결정이 모두 끝난 뒤에만 완료 처리한다. 실행 불가한 필수 항목을 임의로 제외하여 완료하지 않는다. 이번 작업의 완료 범위는 검증된 작업 트리와 결과 문서이며 커밋·푸시·TestFlight 배포는 별도 후속 요청에서 진행한다.
