# 남은 작업이 있는 동안 유지하는 잠금 화면 실시간 카드

작성일: 2026-09-17
상태: todo/doing 카드·상태별 액션 구현 및 최종 플랫폼 게이트 완료. iPhone·iPad 알림 센터의 실제 Activity 전환 검증 통과. 상세 검증 범위는 [결과 문서](CARRYOVER_AND_REVIEW_DISCOVERY_RESULTS.md)를 따른다.
연결 계획: [이월함·회고 탐색 개선](CARRYOVER_AND_REVIEW_DISCOVERY_PLAN.md).

## 요청과 확인 결과

사용자의 최종 요청은 **오늘의 할 일 또는 진행 중 작업이 하나라도 남아 있으면 실시간 카드를
활성화하고, 둘 다 없어지면 카드를 없애는 것**이다. 할 일 카드에는 시작 버튼을,
진행 중 카드에는 완료 버튼을 제공한다. 이전의 ‘이미 시작한 Activity에서만 대기 화면을 유지’
기본안은 이 요청으로 대체한다.

구현 전에 확인한 차이는 다음과 같다. 아래 표는 변경 전 진단 기록이다.

| 확인 지점 | 현재 코드 | 요청과의 차이 |
|---|---|---|
| `PlanBaseTaskLiveActivity.swift`의 일반 작업 액션 | 화살표는 `AdvancePlanBaseTaskIntent`, 완료는 `CompletePlanBaseTaskIntent` | 일반 작업용 시작 버튼과 대기 상태 분기가 없음 |
| `PlanBaseTaskIntentRuntime.swift:133`의 `.advance` | 현재 작업을 todo로 되돌리고, 다음 작업이 todo면 즉시 doing으로 변경 | 표시할 작업 탐색과 상태 변경이 한 동작에 묶임 |
| `TaskLiveActivityCoordinator.swift:84` | 오늘 doing이 없으면 모든 Activity 종료 | todo만 있는 최초 상태에서 생성되지 않고, todo가 남아 있어도 종료됨 |
| `PlanBaseTaskActivityAttributes.ContentState` | 진행 세션·타이머 중심, 시작 가능/선택 상태 없음 | 대기 작업을 정확한 상태로 표현할 계약이 없음 |
| `PlanBaseLockScreenWidget.swift:251` | 정적 잠금 화면 위젯의 `.startable`에만 `▶`와 Start Intent 존재 | 기존 시작 버튼 추가는 실시간 카드와 다른 화면에 적용됨 |

기존 `LOCK_SCREEN_TASK_LIVE_ACTIVITY_PLAN.md`에는 실시간 카드는 doing이 있을 때만 존재하고,
화살표는 실제 상태를 바꾸며, todo의 시작 버튼은 정적 위젯에 둔다고 명시되어 있다.
따라서 단순히 버튼이 가려진 문제로 판단하지 않는다. **기존 설계와 이번에 원하는 흐름의 차이**가 소스에서 확인된다.

구현 전 조사에서 `swift test --filter 'todayTaskWidgetRules|lockScreenWidget'`는 11개 통과했다.
로그는 `.local/carryover-review-discovery/lock-screen-existing-rules.log`다.
이 결과는 기존 조회·선택·스냅샷 규칙의 통과이며, 새 대기 카드나 실제 잠금 인증 동작의 검증을 뜻하지 않는다.
기존 모바일 action gate 테스트는 이번 조사에서 재실행하지 않았다.

## 동작 기준

**일반 작업 카드의 활성 조건은 `오늘 todo 수 + 오늘 doing 수 > 0`이다.**
할 일만 있어도 카드의 생성 대상이며, 진행 중 작업이 없다는 이유로 종료하지 않는다.
시스템 권한·수명·실행 제한과 사용자의 직접 해제는 아래 별도 처리 기준을 따른다.

변경은 남은 작업 중 표시할 작업만 선택한다. Task 상태와 진행 시간 기록은 시작/완료를
명시했을 때만 변경한다. 새롭게 상태를 확인할 때 유효한 사용자 선택을 유지하고,
선택이 없거나 무효라면 진행 중 우선, 그다음 할 일의 기존 결정적 순서로 선택한다.

| 상황 | 표시 | 변경 | 시작/완료 |
|---|---|---|---|
| 처음부터 할 일만 있음 | 새 실시간 카드에 선택한 할 일·`할 일` | 다른 남은 작업으로 순환 | `시작`으로 해당 작업만 doing |
| 선택한 카드가 할 일 | 할 일 제목·`할 일`·오늘 완료 수 | 할 일과 진행 중 모두 탐색 가능 | `시작` 버튼, 완료 버튼 없음 |
| 선택한 카드가 진행 중 | 진행 작업 제목·경과 시간·오늘 완료 수 | 할 일과 진행 중 모두 탐색 가능 | `완료` 버튼, 시작 버튼 없음 |
| 한 작업 완료 후 다른 할 일/진행 중이 남음 | 다음 유효 작업으로 같은 카드 갱신 | 남은 작업 순환 | 새 카드의 상태에 맞는 버튼 |
| 오늘 할 일과 진행 중이 모두 없음 | Activity 종료 및 잠금 화면에서 제거 | 없음 | 이미 완료한 작업을 자동 재시작하지 않음 |
| 표시 대상이 삭제/보관/다른 날짜로 이동 | 최신 유효 대상 재선정 | 오래된 대상을 건드리지 않음 | 최신 상태를 확인하고 실패/갱신 처리 |
| 집중/휴식 모드가 활성 | 기존 Focus 화면 | 일반 작업 선택과 섞지 않음 | 기존 일시정지·재개·종료 동작 유지 |

- 할 일과 진행 중이 섞여 있어도 변경으로 남은 작업을 모두 순환할 수 있어야 한다. `first(where:)`만 다시 선택해 같은 작업으로 돌아오지 않게 한다.
- 변경 버튼에는 `표시할 작업 변경`, 시작에는 `이 작업 시작`, 완료에는 `이 작업 완료`라는 분명한 접근성 의미를 제공한다.
- 남은 작업 전체가 1개일 때만 변경 버튼을 숨기거나 비활성화한다. 다른 todo를 자동으로 시작하지 않는다.
- 마지막 진행 작업을 완료해도 todo가 남으면 할 일 카드로 전환한다. 마지막 todo를 시작해도 같은 카드가 진행 중 표현으로 바뀐다.
- 할 일 카드에는 경과 타이머와 진행 중 활성 점을 보여주지 않는다. 제목·`할 일`·오늘 완료 수·변경/시작 버튼을 사용한다.
- 선택한 todo의 시작은 그 작업만 doing으로 바꾸며 다른 진행 작업을 중단하지 않는다. 보드의 기존 다중 진행 의미를 보존한다.
- 다른 진행 작업이 있다는 이유만으로 선택한 todo의 명시적 시작을 거절하지 않는다. 현재 Start Intent의 ‘doing이 하나도 없어야 함’ 검사와 새 탐색 범위의 충돌을 해결한다.
- 전체 후보가 1개면 해당 상태의 시작 또는 완료 버튼만 제공한다. 아무 후보도 없으면 즉시 제거 정책으로 종료한다.
- 완료 시 미래 알림 확인을 앱으로 연결하는 기존 보호를 유지한다.

## 표시 수명과 기존 위젯의 역할

- 앱 실행/활성화, 오늘 작업 추가·변경, 수신한 데이터 갱신에서 남은 작업을 재평가한다. 시스템이 시작을 허용하는 실행 상황이면 todo만 있어도 Activity 하나를 생성한다. 이미 활성 카드가 있으면 새로 만들지 않고 갱신한다.
- 정적 잠금 위젯은 선택 사항이다. 실시간 카드의 첫 생성과 할 일 표시를 위해 위젯 설치나 선행 doing 전환을 요구하지 않는다. 기존 정적 위젯의 시작 동작은 유지한다.
- 할 일 → 진행 중, 진행 중 → 완료/할 일, 후보 변경만으로 Activity를 종료·재생성하지 않는다. 마지막 남은 작업이 완료되면 즉시 제거한다. 삭제/다른 날짜 이동으로 오늘 후보가 0개가 된 경우도 종료하되 ‘모두 완료’ 사실을 만들어내지 않는다.
- Focus/휴식 화면은 기존 우선순위로 표시한다. Focus가 끝나면 오늘 todo/doing이 남아 있을 때 일반 작업 카드로 돌아간다. 일반 작업 0개라는 이유로 실행 중인 Focus까지 종료하지 않는다.
- 자정·시간대 변경에는 실제 오늘의 후보를 재조회한다. 전날 작업은 기존 이월함 의미를 따르고 새 날짜 카드에 몰래 포함하지 않는다.
- 사용자가 직접 카드를 해제하거나 실시간 현황 허용을 끈 경우 자동 재생성 루프를 만들지 않는다. 당일 수동 해제는 존중하고, 사용자의 명시적인 시작/재개 동작은 허용되는 상황에서 새 카드를 만들 수 있게 한다.

Apple 문서상 하나의 Live Activity는 최대 8시간 활성 상태를 유지하며, 종료 후 잠금 화면에
최대 4시간 더 남을 수 있다. **남아 있는 종료 카드와 활성 카드를 같은 것으로 취급하지 않는다.**
시스템 수명을 다한 경우 앱 재활성화 등 시작이 허용되는 시점에 남은 작업을 재평가하여 새 카드로
복구한다. 다만 ActivityKit의 `dismissed`는 사용자와 시스템 해제를 함께 뜻하며 정확한 원인을 제공하지 않는다.
따라서 생성 시각을 기준으로 관찰한 8시간 만료만 복구하고, 원인 불명의 사라짐은 당일 자동 재생성을 억제한다.
명시적 시작/재개 또는 다음 날의 허용된 실행 시점에는 다시 평가한다. 백그라운드에서 무기한 자동
재생성하거나 앱 실행 없이 새 작업이 즉시 표시된다고 약속하지 않는다.
([Apple ActivityKit 문서](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities))

일반 시작은 앱의 foreground에서, 지원하는 백그라운드 시작은 `LiveActivityIntent` 등의 허용된
경로에서 수행한다. 시스템이 시작을 허용하지 않으면 다음 허용 시점에 재평가하며 Task 상태를
잘못 바꾸어 우회하지 않는다. 별도 APNs 서버나 무기한 백그라운드 실행을 추가하지 않는다.
([LiveActivityIntent 문서](https://developer.apple.com/documentation/AppIntents/LiveActivityIntent))

실제 해제 원인의 제약: [ActivityState.dismissed](https://developer.apple.com/documentation/activitykit/activitystate/dismissed), [ActivityState.ended](https://developer.apple.com/documentation/activitykit/activitystate/ended). 수명 정책 테스트는 시간을 주입하며 8시간 실제 대기 결과로 기록하지 않는다.

## 구현 계획

1. 공통 규칙에 할 일/진행 중/종료의 표시 상태, `todo + doing > 0` 활성 조건, 두 상태를 함께 순환하는 후보 선택을 정의한다. 오늘 작업의 기존 eligibility·대표 수렴·정렬을 재사용한다. 이월 작업은 오늘로 이동하기 전까지 후보에서 제외한다.
2. 표시할 논리 task ID와 후보/Activity의 버전을 기기 로컬 상태로 관리한다. 제목이나 타이머를 수정해 선택 결과를 저장하지 않는다. 프로세스 재시작·reconcile 후에도 유효한 선택을 유지한다.
3. Intent의 표시 변경과 Task 시작/완료를 분리한다. 상태 변경은 `TaskLifecycleService`와 같은 저장 명령으로 진행 이벤트까지 처리한다. 보기 변경에서는 `updatedAt`이나 진행 이벤트를 쓰지 않는다.
4. 기존 정적 위젯의 Start Intent는 보존하고, 실시간 카드의 시작에는 선택 대상·날짜·버전을 검증할 수 있게 한다. 다른 진행 작업의 존재와 선택한 작업의 유효성을 분리한다. 오래된 후보·완료된 작업·이미 시작한 동일 작업의 중복 시작을 막고 화면을 갱신한다.
5. 연속 변경·시작·완료 입력을 검증한다. 기존 1초 gate 때문에 유효한 ‘선택 후 시작’이 조용히 무시되지 않도록 액션별 중복 방지와 최신 상태 검사를 설계한다.
6. Coordinator가 최초 todo만 있는 상태에서도 생성하고, 모든 todo/doing이 사라질 때 종료하도록 연결한다. 기존 doing 세션 중심 `handledSessionIDs`만으로 todo 카드를 차단하지 않게 Activity의 생성·수동 해제·시스템 만료 상태를 관리한다. Focus 우선순위와 8시간 처리의 충돌을 해결하고, 모델 저장 성공 후 화면 갱신 실패가 발생해도 상태를 중복 변경하지 않는다.
7. ContentState의 새 필드는 기존 payload를 해석할 수 있는 기본값/호환 디코딩을 둔다. 기존 wire key `updatedAt`과 실행 중 Activity 호환성을 확인한다. 배포 SwiftData 스키마는 변경하지 않는다.
8. 잠금 화면 카드에 할 일/시작 및 진행 중/완료 표현을 적용한다. 공용 상태를 사용하는 Dynamic Island는 할 일을 진행 중 타이머로 잘못 표시하지 않도록 최소한의 상태 분기만 적용한다. 별도 레이아웃 재디자인은 하지 않는다.
9. 기존 계획의 ‘doing이 없으면 항상 즉시 종료’, ‘화살표가 상태를 바꿈’ 항목과 아키텍처 문서를 새 동작에 맞춰 정리한다. 과거 출시 기록은 당시 동작으로 보존한다.

## 검증과 완료 기준

`[x]`는 결과 문서의 공통 규칙 테스트 또는 격리 Simulator UI에서 확인한 범위다.
수동 해제·8시간 만료·원격 변경은 주입된 로컬 정책 검증이며, 실기기 시스템 검증으로 해석하지 않는다.
미확인 시스템/실기기 항목은 아래와 결과 문서에 남긴다.

- [x] 처음부터 todo만 있는 상태로 앱을 실행하면 정적 위젯 설치/선행 작업 시작 없이 실시간 카드가 생성됨.
- [x] todo A/B와 doing C/D가 섞인 상태에서 모두 순환되며, 보기 변경만으로 상태·진행 이벤트·누적 시간이 바뀌지 않음.
- [x] 마지막 진행 완료 후 todo A/B/C가 남으면 할 일 카드가 유지됨. 변경만으로 시작되지 않음.
- [x] 선택한 todo 시작 시 해당 작업만 doing, started 이벤트 한 번 기록, 같은 Activity에 올바른 제목·시간·완료 버튼 표시. 기존 다른 doing은 유지.
- [x] 후보 1개에서 변경 버튼 없음, 후보 0개에서 카드 즉시 제거, 완료 작업 재등장 없음, 정적 위젯의 기존 시작 흐름 검증.
