# 집중모드 화면과 예상 시간 반영

작성일: 2026-09-04

## 제품 기준

- 작업 예상 시간이 있으면 새 집중의 기본 시간으로 제안한다. 없거나 유효하지 않으면 25분이다.
- 한 번의 집중은 기존 5~120분 범위다. 범위 밖 예상 시간은 제한과 원래 예상 값을 화면에 설명한다.
- 사용자가 선택한 프리셋·직접 조절 값이 우선이며 원래 작업의 예상 시간은 수정하지 않는다.
- 이미 시작한 세션과 이어 집중·휴식 종료 알림 동작은 세션에 확정된 시간을 사용한다.
- 작업의 일반 진행 시간은 실제 집중 시간과 의미가 달라 예상 시간에서 자동 차감하지 않는다.
- 완료·진행 기록과 타이머 snapshot의 기존 의미, V10 스키마·백업 V9을 유지한다.

## 화면 개선

- 선택 작업을 요약 카드로 표시하고 작업 검색·변경을 별도 목록에 둔다.
- 집중·휴식 시간 조절, 프리셋, 예상 시간 복원, 시작 동작을 순서대로 배치한다.
- 실행 화면은 남은 시간·종료 예정 시각·일시정지를 중심으로 구성한다.
- 큰 글자와 작은 창·가로 화면은 전체 스크롤과 세로 버튼 배치를 사용한다.
- 집중 종료 전 기록/작업 상태를 안내하고, 작업 완료는 별도 확인하며 예정된 알림도 안내한다.
- 종료 화면은 실제 집중 결과와 휴식·다음 집중으로 이어지고 완료한 작업의 재시작을 숨긴다.
- Mac의 항상 위 표시를 사용자가 끌 수 있게 하고 Watch에도 같은 예상 시간 기본값을 적용한다.
- UI 테스트의 활성 타이머와 알림 토큰은 실제 App Group 대신 프로세스별 임시 디렉터리에 둔다.

## 검증

- 시간 기본값/범위/정수 경계, 사용자 지정 우선, 실행 중 예상 변경 독립성, 오래된 작업 직접 선택.
- iPhone·iPad: 예상 시간 → 프리셋 → 예상 복원 → 시작 → 일시정지 → 화면 닫기/복귀 → 종료 → 휴식.
- 밝은/어두운 테마, 큰 글자, 가로 화면, 작업 완료 확인 및 완료 후 잘못된 재시작 방지.
- 실제 Mac 480×700 화면·항상 위 표시, 공통 테스트와 iOS/macOS/watchOS 전체 빌드.
- 실제 알림 도착 시각·잠금 화면·기기 간 동기화는 기존 Focus 실기기 인수 범위를 유지한다.

## 완료 결과

2026-09-04 구현과 로컬 검증 완료. 결과는 `.local/focus-polish/`에 보관한다.

- `verify-platform-builds.sh` 성공: Debug 385개, Release 384개 테스트, iOS/macOS Debug·Release 및 내장 Watch 앱·위젯 빌드/번들 검증.
- 전체 게이트 이후 작업 검색창과 상태 전환 스크롤을 보정하고 iPhone 17e·iPad A16에서 집중 UI 시나리오 3개씩 총 6개를 재실행해 통과했다. 밝은 테마·어두운 테마·실제 AX5·가로 화면을 포함한다.
- 작업을 눌러 열 때 다른 작업이 선택되던 iOS 초기 전달 문제, iPad 검색창 누락, 큰 글자의 시작 직후 스크롤 위치 문제를 수정했다.
- Mac 최종 Debug 빌드 성공. 예상 30분 적용 → 15분 선택 → 예상 복원 → 시작·일시정지·종료 기록 및 작업 검색 후 45분 자동 적용을 확인했다.
- Mac 항상 위 설정이 즉시 창에 적용되도록 설정값을 동기적으로 읽은 뒤 창에 전달한다. 실제 창 layer가 3 → 0 → 3으로 전환되는 것을 확인했다.
- 대표 화면: `focus-iphone-setup.png`, `focus-iphone-running.png`, `focus-ipad-search.png`, `focus-mac-setup.png`, `focus-mac-running.png`.
- UI 검증은 메모리 데이터와 임시 타이머 저장소를 사용했다. 영속 스키마 변경은 없다.
