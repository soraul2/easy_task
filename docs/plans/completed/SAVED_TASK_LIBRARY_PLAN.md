# 저장한 작업

- 작성일: 2026-09-04
- 범위: macOS, iPhone·iPad 칸반에서 단일 작업 저장·재사용
- 상태: 구현·화면·전체 회귀 검증 완료

## 사용자 흐름

1. 작업 카드의 메뉴에서 `자주 쓰는 작업으로 저장`을 선택한다.
2. 빠른 입력 옆 `저장한 작업`을 열고 제목·메모·태그·체크리스트로 검색한다.
3. 즐겨찾기를 고르거나 현재 보드 날짜에 필요한 작업을 개별 추가한다.
4. 저장 목록에서 새 작업을 직접 작성하고 저장 내용 편집·삭제도 할 수 있다.

한 번 추가한 행은 `추가됨`으로 바꿔 연속 입력에 의한 중복을 줄인다. 같은 화면에서
동일 작업이 또 필요하면 메뉴의 `한 번 더 추가`를 사용한다. 목록을 닫았다 다시 열어도
저장본은 남는다. 완료 여부와 관계없이 필요한 날마다 새 작업을 만들 수 있다.

## 저장·동기화 경계

첫 버전은 기존 `TaskTemplate`과 `TaskTemplateItem`을 사용한다. 논리 항목이 정확히
하나인 템플릿을 저장한 작업으로 표시하므로 기존 단일 작업 템플릿도 사용할 수 있다.
새로 저장한 작업은 기존 템플릿 목록에서도 보이고 즐겨찾기·편집·삭제를 공유한다.
화면에서 이 관계를 안내하며, 삭제 전 템플릿 목록에서도 제거된다는 것을 알린다.
다중 작업 템플릿은 이 목록에 포함하지 않는다. 이름 접두사나 seedKey를 구분자로 사용하지 않는다.

V10 스키마, 백업 V9, CloudKit 식별자를 변경하지 않는다. 새 영속 모델과 Production
스키마 배포 없이 기존 동기화·백업 경로를 이용한다. 중복 레코드는 기존 무결성의
최신 수정·instanceID 우선순위로 대표를 선택하며, 실행 시 ID 범위를 다시 조회한다.
조회 뒤 다중 항목 템플릿으로 바뀌거나 삭제된 항목은 적용·편집·삭제하지 않는다.

보드에 꺼낸 작업은 독립 Task다. 제목·메모·우선순위·태그·예상 시간·체크리스트 제목만
복사하고 새 ID와 생성 시각을 부여한다. 날짜는 선택한 보드 날짜, 상태는 `할 일`,
체크리스트는 미완료로 시작한다. 원본의 완료·이월·알림·이벤트·템플릿 배치 연결과
진행·집중·완료 활동 이력은 복사하지 않는다. 저장본을 수정·삭제해도 꺼낸 작업은 유지된다.

쓰기 작업은 `PersistenceCommandService.perform`으로 저장/rollback과 알림을 통합한다.
목록을 열거나 데이터가 바뀌면 템플릿 자료만 256개 단위로 읽어 값 스냅샷으로 표시한다.
삭제된 SwiftData 모델을 화면이 계속 참조하지 않도록 영속 객체 배열을 시트에 전달하지 않는다.
Task 전체 조회를 추가하지 않으며, 한 작업의 저장·추가·수정·삭제는 논리 ID나 선택한 날짜로 제한한다.

## 검증

- 단위 테스트: 원본 내용 복사·날짜·순서·새 ID·활동 및 알림 초기화, 저장본 수정·삭제의
  기존 작업 독립성, 검색·즐겨찾기와 동기화 중복, 잘못된 입력 rollback과 오래된 선택,
  기존 백업 내보내기·복원 후 재사용, 270개 목록의 페이지 경계와 삭제 후 값 안전성.
- iPhone·iPad UI 각 2개 통과: 카드에서 저장 → 저장 내용 편집 → 체크리스트 검색 → 추가
  → 목록 재열기·삭제, 가장 큰 글자와 미래 날짜에 추가. 최종 스크린샷도 확인했다.
- macOS: 실제 화면에서 저장 목록·새로 저장을 열고 저장본 생성 → 보드에 추가 확인.
- 큰 글자에서는 날짜·설명을 줄바꿈하고 전체 내용을 스크롤한다. 검색 후 추가하면 키보드를 닫는다.
- 전체 회귀 게이트 통과(`scripts/verify-platform-builds.sh`, exit 0): Debug 380개·Release
  379개 공통 테스트, iOS·macOS Debug/Release 빌드와 내장 Watch·위젯·개인정보 매니페스트 검증.
- 이번 변경은 로컬 소스에 반영했다. TestFlight 업로드·원격 push·병합은 이 작업 범위에 포함하지 않았다.
