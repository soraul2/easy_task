# 메모 생성 유형 분리

상태: 구현·로컬 기능 검증 완료 (2026-09-16). 남아 있던 macOS 화면 검증을 격리 앱에서 완료했다. 출시 승인이나 실제 CloudKit 데이터 영향 확인을 뜻하지 않으며, 아래의 과거 검증 경계 이탈 기록은 유지한다.

## 목표와 경계

새 메모는 글 메모 / 체크리스트 / 필기·그림 중 하나를 선택하여 만든다. 내용 작성
전에는 유형을 다시 선택할 수 있고, 작성 뒤에는 선택한 편집기를 유지한다. 기존
복합 메모는 내용에 접근할 수 있도록 기존 방식 전환 UI를 유지한다.

시작 시 Duo 적응형 UI 변경이 작업 트리에 있었다. 시작 diff와 해시는
`.local/memo-types/starting-diff.patch`, `starting-state.json`에 보존했다.
기존 iPad 목록/편집기 분할과 루트 편집 세션·커서·키보드 보존 구조를 유지한다.
iCloud Drive와 `.local/backups/`, 운영 CloudKit, 업로드·push는 작업 범위 밖이다.

## 설계

- 영속 스키마·식별자·백업 형식은 변경하지 않는다.
- `preferredModeRawValue`는 기존 편집기 선호 의미를 유지한다. 실제 비어 있지 않은
  텍스트·필기·체크리스트로 단일/복합 편집 정책을 계산한다. 단일 내용이 있으면 해당
  편집기를 열고, 모두 지운 기존 메모는 저장된 방식을 유지한다.
- 구버전 앱에서 다른 종류의 내용을 추가하면 복합 메모로 열 수 있다. 새 유형을
  표현하려고 구버전이 모르는 raw value를 저장하지 않는다.
- 생성 유형 선택·빈 체크 항목·취소만으로 레코드를 만들지 않는다. 처음 실제 내용을
  작성한 뒤 유형을 잠그며, 신규 단일 편집 세션은 다른 종류의 쓰기를 허용하지 않는다.
- 기존 복합 메모의 저장은 모든 종류를 보존한다. 편집 세션은 동기화 후와 저장 직전에
  수정하지 않은 종류의 최신 내용을 다시 읽어, 오래된 스냅샷으로 덮어쓰지 않는다.
  같은 종류의 동시 편집은 기존 저장·수렴 규칙을 따른다.
- 동기화 중 중복 수렴으로 물리 레코드가 바뀌어도 논리 ID의 활성 대표를 기존 무결성
  정렬로 찾아 세션을 연결한다. 고정만 저장할 때도 이전 레코드를 갱신하지 않는다.
  활성 메모가 사라지면 자동 재생성하지 않고 저장 실패와 로컬 초안을 유지한다.
- 목록 요약은 기존 40개 페이지에 속한 메모 ID로만 자식 정보를 조회한다. 필기는
  목록에서 메타데이터만 읽고, 보이는 행에서 최대 240px 미리보기를 만든다.
- macOS의 필기·그림은 기존 미리보기·지우기 지원 범위를 유지한다. 새 빈 캔버스에는
  iPhone·iPad에서 작성할 수 있음을 안내하며 빈 메모를 동기화용으로 저장하지 않는다.

초기 UI 검사 각 1건 실패는 검색 창이 접힌 상태에서 검색 필드를 바로 찾던 테스트
문제였다. 목록을 내려 시스템 검색 창을 표시한 뒤 검사하도록 수정했고 두 기기의
후속 검사에서 모두 통과했다. 최초 실패 결과는 삭제하지 않는다.

첫 전체 게이트 이후 DEBUG 테스트 초기화·단위 테스트와 macOS 저장 상태 문구를
수정했다. macOS 문구 수정은 최종 게이트가 SwiftPM Release를 컴파일하고 플랫폼
빌드를 시작하기 전에 반영했고 해시 기록에도 시점을 남겼다.
그 뒤 중복 수렴으로 대표 레코드가 바뀔 때 열린 세션이 이전 레코드를 계속 참조하는
문제를 로컬 테스트로 재현했다(`core-representative-before-fix.log`). 최신 대표를
찾아 연결하도록 보완했으므로 `full-gate-final.log`는 보완 전 후보의 결과다.
현재 소스의 최종 전체 게이트는 `full-gate-convergence.log`로 별도 검증한다.
최신 앱에서 재실행·저장 실패·복합 메모 화면 회귀도 다시 확인한 뒤 결과를 추가한다.
`ios-convergence-build.log` 테스트 빌드와 `macos-convergence-build.log` Debug 빌드는
종료 0이다. 최신 UI 결과는 `iphone-convergence-regression.xcresult` 3/3,
`ipad-convergence-regression.xcresult` 2/2로 모두 통과했다. 각각 세 유형 재실행·저장
실패 재시도와 복합 메모·입력 상태의 열 전환 보존을 확인했다. 현재 요구사항별 증거와 미완료 항목은
`.local/memo-types/COMPLETION_AUDIT.md`에 기록한다.

## 중단 당시 검증과 재개 조건 (아래 최종 검증으로 해소)

다음은 오후 작업 중단 당시의 기록이다. 현재 상태는 다음 절의 최종 검증을 따른다.

- macOS에서 최신 동기화 보완본으로 빈 초안 재선택·취소, 글/체크 자동 저장,
  체크 항목 수정·정렬·완료·고정, 실제 앱 재실행 후 상태 보존, 본문 검색·테스트 메모
  삭제를 확인했다. 기존 복합 메모와 단일 필기의 큰 캔버스 미리보기도 CUA 화면으로 확인했다.
- macOS 목록의 작은 필기 미리보기가 흰 영역으로 표시되는 문제를 발견했다.
  원본 색상 렌더링만으로 해결되지 않았다. PencilKit NSImage를 bitmap으로 구체화하는
  보완은 `macos-thumbnail-raster-build.log`, `macos-thumbnail-release-build.log`에서
  Debug/Release 모두 종료 0이나 실제 화면에서는 아직 확인하지 못했다.
- 전체 게이트 이후 바뀐 제품 파일은 macOS 메모 화면의 이 미리보기 부분뿐이다.
  공통 코어와 iOS는 게이트 기준 해시와 일치한다. 현재 소스 해시는
  `.local/memo-types/current-source.json`, 미리보기 변경 해시는 `mac-thumbnail-source.json`이다.
- Mac이 다시 잠겨 미리보기 보완 화면, 필기 지우기 취소/확인과 다른 내용 보존,
  최종 어두운 화면 확인이 남아 있다. 마지막 CUA 재확인에서도 잠금으로 접근이 거절됐다.
  기존의 잠금 해제 요청은 여전히 필요하며 자동 테스트나 빌드 프로세스는 모두 종료됐다.
- 같은 화면 잠금이 연속 세 goal turn에서 재확인되었고, 마지막 확인 시 소스 해시는
  직전 검증 기록과 일치하며 실행 중인 검사도 없었다. goal은 blocked로 전환한다.
  재개 조건은 Mac 잠금 해제와 남은 검증 동안 잠금 해제 상태 유지다. 재개 시 원래 앱이
  아닌 격리 복사본에 최신 bitmap 보완을 반영하고 위 세 가지 화면 항목부터 확인한다.
- 사용자 변경 중 메모 화면과 UI 테스트를 제외한 기존 Duo 파일은 시작 해시와 일치한다.
  메모의 루트 소유 편집 세션·커서/포커스 보존은 유지하며 관련 UI 검사로 확인했다.

## 검증 도구의 의도하지 않은 일반 실행

macOS 메모리 테스트 앱을 종료한 뒤 접근성 상태를 요청했을 때, 도구가 원래 Debug 앱을
`--ui-testing` 없이 자동 재실행했다. 즉시 종료했다. PID 56350 시스템 로그에는
CloudKit setup/import/export와 레코드 수정 완료 로그가 있었다. 레코드와 환경 정보가
비공개여서 실제 변경 범위나 Production 여부는 단정할 수 없다. 해당 실행에서 직접
메모를 수정·삭제하거나 복원하지 않았으며 사용자에게 사건을 알렸다.

증거는 `.local/memo-types/unintended-macos-relaunch.log`, 설명은
`macos-ui-observations.md`에 보존한다. 이후 macOS 검증은 별도 bundle ID, 빈 CloudKit
entitlement와 고정 `--ui-testing`/로컬 저장소 인자를 가진 `PlanBaseMemoUITests.app`만
사용한다. 일반 앱 설정이나 데이터에 복구를 시도하지 않는다. 모든 실행이 CloudKit과
격리되었다고 보고해서는 안 된다.
