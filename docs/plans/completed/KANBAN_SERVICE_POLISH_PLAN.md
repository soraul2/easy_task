# 칸반 화면·버튼·테마 완성도 개선

- 목표: 칸반의 기능과 시각 언어가 자연스럽게 이어지고 일상적으로 사용할 수 있는 품질.
- 범위: iPhone·iPad 칸반, 연결된 저장 작업·템플릿·작업 편집·테마 선택, macOS 동등 동작.
- 데이터 스키마와 상태 전환·알림·활동 기록의 의미는 유지한다.
- 완료: 2026-09-04. 구현, 시뮬레이터 교차 검증, 실제 Mac 검증을 마쳤다.

## 구현 방향

- 빠른 입력과 저장한 작업/템플릿 불러오기를 분리하고, 칸반에서 테마 선택에 바로 진입한다.
- 카드 제목을 상세 편집 진입점으로 만들어 아이콘 수를 줄이고 제목 너비를 확보한다.
- 카드·상태 버튼의 그림자를 줄이고 동일한 버튼 스타일에서 테마별 글자 대비를 해결한다.
- 테마 전환은 Observable 상태를 통해 색상 의존 뷰를 갱신한다. 화면 identity를 교체하지 않아
  작성 중인 입력, 선택한 상태, 체크리스트 펼침 상태가 사라지지 않게 한다.
- 모든 화면 높이에서 보드를 스크롤할 수 있게 하고 iPad 목록의 줄 길이를 제한한다.
- 저장한 작업 기능은 직전 구현과 같은 데이터/백업 경계를 유지한다.

검증 자료: `.local/kanban-polish/`. 업로드·원격 병합은 이 작업의 완료 기준에 포함하지 않는다.

## 시뮬레이터에서 발견해 수정한 문제

- 테마 전환 때 보드 identity를 바꾸면서 입력 중인 제목과 선택 상태가 사라지는 문제를
  Observable 팔레트로 해결했다. 날짜·필터·초안 유지와 재실행 후 테마 복원을 UI로 검증한다.
- 작업 삭제 후 사라지는 카드가 SwiftData에서 분리된 Task의 `tags`를 읽어 종료되는 문제를
  재현했다. 모바일 카드 표시를 값 snapshot으로 분리했고 삭제 취소·확정·빈 화면 및
  체크리스트 편집 회귀 테스트가 통과했다.
- 밝은 테마에서 어두운 테마로 변경할 때 sheet의 시스템 글자와 버튼 배경이 뒤섞이는
  문제를 발견했다. sheet 밝기를 명시하고 테마 완료 버튼은 공유 배경과 분리했다.
- 버튼용 채움색과 일반 텍스트·아이콘용 강조색을 구분해 11개 팔레트의 대비를 보정했다.
- iPad 가로 화면은 최대 너비 820pt로 제한하고 큰 글자에서는 입력/불러오기/상태 UI를
  세로로 배치한다. 일반 글자에서도 보드 전체를 스크롤할 수 있다.

## 검증 기록

- `phone-flow.xcresult`: iPhone 가로 화면, 테마 변경, 저장 작업 기본/AX5 흐름 4개 통과.
- `phone-matrix.xcresult`: 체크리스트, 완료 알림 보존, 집중 진입, 세로 스크롤, 테마 접근 통과.
  삭제 crash와 44pt 부동소수점 비교 실패가 발생해 이후 수정했다.
- `phone-fixes.xcresult`: 삭제 취소·확정, 체크리스트, 테마 변경 3개 재검증 통과.
- `ipad-final.xcresult`: 11개 테마, 가로, 삭제, 테마 변경, 저장 작업 기본/AX5 6개 통과.
  11개 팔레트와 가로/큰 글자 스크린샷을 직접 검토했다.
- `phone-appearance.xcresult`: 작은 iPhone 17e에서 테마 변경과 저장 작업 관리 2개 통과.
  상단 완료 버튼 대비가 충분하지 않아 추가 수정 중에 수집한 자료다.
- `phone-toolbar-final.xcresult`: 최종 테마 변경·초안 유지·다크 저장 편집 흐름 통과.
  `ipad-toolbar-final.xcresult`: 같은 테마 변경 및 저장 작업 편집·재사용·삭제 2개 통과.
  양 기기의 최종 완료/저장 버튼 스크린샷을 직접 검토했다.
- `phone-final-matrix.xcresult`: 작은 iPhone 17e의 11개 테마, 가로, 탭 이동, AX5 저장 작업
  4개 통과. 회고 진입 테스트의 기존 "테마 버튼 없음" 조건은 이번 진입점 추가와 충돌해
  "테마 버튼 접근 가능"으로 갱신했다. `phone-review-final.xcresult`에서 회고 진입·취소 통과.
  11개 테마의 보드, 진행/완료, 가로/큰 글자 스크린샷 직접 검토를 마쳤다.
  이 실패의 추가 Simulator 로그 수집은 기대값 수정과 재검증 후 중단했으며,
  테스트 결과와 스크린샷은 정상적으로 xcresult에서 내보냈다.
- `full-verification-final.log`: Debug 공통 테스트 382개, Release 381개 통과.
  iOS와 포함된 Watch 앱·위젯, macOS 앱·위젯 Debug/Release 빌드 및 번들/manifest 검증이
  모두 통과했다. 전체 검증 스크립트 종료 코드 0을 확인했다.
- `macos-ui-ready.log`: 마지막 수정본의 별도 macOS Debug 빌드도 통과했다.
  `.local/DerivedData-archive-review/Build/Products/Debug/PlanBase.app`을 `--ui-testing`으로
  실행해 메모리 저장소로 실제 화면을 검증했다. 최신 테스트 앱을 새로 실행한 뒤
  접근성 정보를 정상적으로 읽을 수 있어 다음 흐름까지 확인했다.
  - 9월 5일을 선택하고 제목을 입력한 상태에서 Midnight Blue로 변경한 뒤 날짜와 초안 유지.
  - 빠른 입력으로 작업 생성 → 작업 메뉴에서 저장 → 저장 목록에 같은 제목 표시.
  - 선택 날짜에 다시 추가해 할 일 1개가 2개가 되고 추가 완료 피드백 표시.
  - 작업 삭제 확인의 취소 후 2개 유지, 다시 삭제를 확정한 후 1개로 감소.
  - 앱이 계속 실행된 상태에서 남은 작업을 진행 중으로 이동하고 진행 시간 표시 확인.
  밝은 보드, 다크 보드, 저장 목록, 삭제 확인의 실제 스크린샷을 직접 검토했다.
