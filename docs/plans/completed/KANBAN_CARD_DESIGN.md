# 칸반 작업 카드 디자인 개선

2026-09-06. 적용 범위는 macOS 칸반 컬럼과 카드, iPhone·iPad 작업 카드, Apple Watch 오늘 화면의 작업 카드다.

## 디자인 방향

제목을 먼저 읽고, 필요한 정보와 다음 행동을 쉽게 찾는 개인 계획용 카드로 정리한다.
공식 제품 소개·도움말의 공개 화면을 참고했으며 특정 앱의 화면을 복제하지 않는다.

- [Todoist](https://www.todoist.com/help/todoist/features/use-the-board-layout-in-todoist-AiAVsyEI): 차분한 컬럼, 제목 아래 짧은 정보.
- [TickTick](https://ticktick.com/features?language=en_US): 내용에 맞는 카드 높이, 모바일에 맞는 정보 밀도.
- [Things](https://culturedcode.com/things/features/): 필요한 시점에 체크리스트와 상세 내용 펼치기.
- [Sunsama](https://help.sunsama.com/docs/usage-guides/tasks/planned-and-actual-times/): 예상 시간과 사용 시간의 구분, 작업에서 집중으로 연결.

## 적용 내용

- 카드 바탕을 테마의 `panel`로 통일하고 해당 표면의 `primaryText`·`secondaryText`를 사용한다.
- Mac 카드의 그라데이션과 겹친 테두리를 제거한다. 모서리는 Mac 14pt, 모바일 16pt다.
- 진행 중 카드는 작은 상태 심볼과 은은한 강조 테두리로 구분한다. 완료 제목에는 취소선을 적용한다.
- Mac 컬럼은 옅은 중립 배경과 상태 심볼·제목·개수로 구성한다. 집중 진입은 헤더의 작은 바로가기로 유지한다.
- 드래그 중에는 컬럼 헤더 문구와 테두리로 목적지를 표시한다. 안내 영역을 추가해 카드 위치가 밀리는 동작을 없앤다.
- Mac 카드 제목은 여러 줄로 표시하고 직접 편집을 유지한다. 제목 옆에는 편집·저장·삭제 메뉴 하나를 둔다.
- 시간 정보에 예상 시간을 명시하고 기존 진행 시간의 의미를 유지한다. 사용 시간을 완료율로 표현하지 않는다.
- 모바일의 가로 스크롤 정보 칩을 일반 텍스트 정보로 바꾼다. 공간이 부족하면 요약 정보를 세로로 배치하고 알림은 줄바꿈한다.
- 정보 라벨은 하나의 접근성 요소로 읽히게 구성한다. 알림 기록과 체크리스트 진행 정보의 접근성 식별자를 유지한다.
- 모바일 집중 버튼을 하단의 세 가지 상태 컨트롤 옆으로 옮긴다. 접근성 글자 크기에서는 상태 메뉴와 집중 버튼을 세로로 배치한다.
- Mac은 32pt, 모바일은 44pt 이상의 조작 영역을 유지한다. 드래그 대상과 키보드 포커스는 명확히 강조한다.
- 체크리스트 펼침과 저장 오류, 알림 기록, 완료 확인, 상태 전환의 저장 경계는 기존 흐름을 사용한다.

### Apple Watch

- 좁은 가로 한 줄 구성을 제목·보조 정보·조작 버튼의 세 영역으로 나눈다. 제목은 기본 3줄까지, 큰 글자에서는 줄 수 제한 없이 표시한다.
- 14pt 모서리의 중립 카드에 진행 중 상태만 파란 테두리로 표시하고, 완료 제목에는 취소선을 적용한다.
- 상태와 예상 시간을 함께 표시하며 공간이 부족하면 세로로 배치한다. 알림 날짜는 줄바꿈을 허용한다.
- 상태 변경을 `진행 시작`·`완료`·`다시 진행` 텍스트 버튼으로 표시하고 집중 진입과 분리한다. 조작 영역은 최소 44pt다.
- 글자 크기가 `.xxxLarge` 이상이면 두 버튼을 세로로 배치하고 집중 버튼에도 `집중 시작` 문구를 표시한다.
- 기존 상태 전환 서비스와 집중 화면 이동을 유지한다. 큰 글자 검사용 실행 인자는 DEBUG와 메모리 테스트 모드에서만 동작한다.

## 검증

빌드·UI 검증 로그와 화면 자료는 Git에서 제외되는 `.local/kanban-design/`에 보관한다.
이 변경은 영속 모델·CloudKit·백업·위젯·테마 팔레트 값을 변경하지 않는다.

- macOS Debug 빌드, iOS Debug 테스트용 빌드 통과.
- 상태 표시·보드 규칙·체크리스트·테마 관련 공통 테스트 33개 통과.
- iPhone 17e 시뮬레이터에서 UI 테스트 6개 통과: 접근성 글자 크기, 체크리스트 저장·취소·진행 표시, 집중 시작·일시 정지·재개·휴식, 11개 테마 화면, 상태 컨트롤 위에서 세로 스크롤, 미래 알림이 있는 작업의 완료 취소·기록 보존.
- iPad A16 시뮬레이터에서 UI 테스트 3개 통과: 세로·가로 네이티브 화면, 가로 화면 조작, 다크 모드·최대 접근성 글자 크기에서 집중 흐름.
- macOS 테스트 전용 메모리 데이터로 여러 줄 제목 편집, 상태 변경, 집중 설정 열기, 작업 편집 메뉴, 체크리스트 펼침·완료, 밝은·어두운 테마를 직접 확인.
- macOS 드래그는 대상 강조를 확인했으나 자동 조작으로 컬럼 간 실제 이동을 끝까지 재현하지 못했다. 기존 이동 처리 호출은 유지했다.
- watchOS Debug 빌드와 상태·Watch snapshot 관련 공통 테스트 6개 통과.
- Watch 40mm 시뮬레이터의 메모리 데이터로 기본 글자에서 진행 시작·완료·다시 진행, 집중 설정 진입을 확인했다. `.xxxLarge`에서는 긴 제목 줄바꿈, 보조 정보의 세로 배치, 세로 버튼과 진행 시작·집중 설정 진입을 확인했다.

알림 라벨의 접근성 요소 구성을 수정한 뒤 관련 iPhone 테스트 2개를 재실행해 통과했다.
iPad 큰 글자 테스트는 첫 실행에서 지정한 테스트 인자가 누락되는 기존 실행 문제를 피하도록 앱을 다시 실행한 뒤 검증하며, 수정 후 통과했다.
실제 CloudKit 저장소나 실기기 데이터는 사용하지 않았다.

## TestFlight 배포

사용자의 후속 업로드 요청에 따라 2026-09-06 버전 1.0(72)을 iOS·iPadOS·watchOS와 macOS에 업로드했다.

- 전체 플랫폼 Debug/Release 회귀와 공통 테스트 Debug 407개·Release 405개 통과.
- 앱·위젯 여섯 번들의 버전·서명·App Group·CloudKit 권한 검증 통과. Mac은 Apple Silicon·Intel universal 빌드다.
- 컴파일 소스 iOS 190개·macOS 182개가 배포 snapshot과 일치한다.
- 명령행 업로드는 저장된 Xcode 계정의 `missing Xcode-Username` 오류로 전송 전에 실패했다. 로그인된 Xcode Organizer 계정으로 두 플랫폼의 배포 서명과 업로드를 완료했다.
- 최종 배포 서명의 CloudKit Production 권한, iOS 04:00:39 및 macOS 04:04:12 KST 업로드 성공과 Apple 패키지 처리 시작을 확인했다.
- 배포 파일·로그·소스 snapshot과 결과는 `.local/releases/build-72/`에 보관한다. 한국어 테스트 안내는 로컬 파일로 준비했으며 App Store Connect에는 저장하지 않았다.

Apple 처리 완료와 실제 TestFlight 설치 가능 상태는 아직 확인하지 않았다.
