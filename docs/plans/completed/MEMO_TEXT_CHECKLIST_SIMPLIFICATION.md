# 글 메모·체크리스트 중심 메모 정리

상태: 구현·로컬 회귀 검증 완료 (2026-11-27).

## 제품 동작

- 신규 메모는 글 메모와 체크리스트만 만든다. 빈 목록에서 각각 바로 시작할 수 있다.
- 글 메모는 첫 줄을 제목으로 사용하고, 목록은 유형·고정·선택 상태를 표시한다. 검색 결과가 없으면 검색어를 바로 지울 수 있다.
- 체크리스트는 완료 개수·진행 막대와 항목 관리 메뉴를 제공한다. 새 항목은 마지막 빈 항목만 재사용하며 입력 포커스를 유지한다. 큰 글자에서도 완료·관리 버튼이 첫 줄 가까이에 표시된다.
- 기존 필기는 양 플랫폼에서 `이전 필기` 읽기 전용 미리보기로 표시한다. 그림 생성·편집·지우기와 PencilKit 도구 선택기는 제공하지 않는다.
- 기존 복합 메모는 글·체크리스트를 편집하고, 실제 필기 데이터가 있을 때만 이전 필기 보기로 전환한다. 필기 전용·비워진 필기 메모는 읽기 전용 안내를 유지한다.
- macOS 체크리스트는 Enter 또는 추가 버튼으로 다음 빈 항목에 포커스한다. iOS 편집기 내부는 동적 입력 행의 설치·포커스가 안정되도록 일반 VStack으로 구성하고, 메모 목록의 Lazy 구성·페이지 조회는 유지한다.

## 데이터 경계

- V11과 이전 스키마, `drawing` raw value, CloudKit 모델, 백업 형식은 변경하지 않는다.
- `MemoService.savePreservingDrawing`은 글·체크리스트·선호 모드만 저장한다. 화면에서 로드한 필기 snapshot이 비어 있어도 필기 레코드를 교체하거나 지우지 않는다.
- 기존 `saveComposite(drawingData:)`는 백업·호환·fixture 경로로 유지한다. 편집 세션의 기본 저장과 UI 저장 실패 fixture는 보존용 API를 사용한다.
- 저장 전 최신 활성 대표와 수정하지 않은 자식 내용을 읽고, 읽기·저장 실패 시 초안 및 재시도 경로를 유지한다.
- 빈 체크 항목은 DB에 저장하지 않는다. 저장 후 갱신할 때 화면 전용 빈 draft의 ID·제목·완료·순서는 유지하고, 원격의 실제 항목 수정·추가도 반영한다. 같은 ID의 원격 항목이 생기면 중복하지 않는다.
- 실제 사용자 저장소·CloudKit에는 접근하지 않았다. UI 검증은 새 전용 시뮬레이터와 `--ui-testing`의 메모리/격리 로컬 저장소를 사용했다.

## 검증

- 공통 메모 및 관련 백업: Debug 36개, Release 35개 통과. 최종 패키지 전체 테스트는 Debug 777개 통과·42개 skip(총 819개), Release 772개 통과·10개 skip(총 782개).
- `./scripts/verify-platform-builds.sh`: 최종 build 96 커밋 `f231ee8`에서 exit 0. 위 패키지 테스트와 iOS/macOS Debug·Release, 내장 Watch 앱·위젯 빌드·번들 검증을 포함한다. 최종 iPhone·iPad UI와 signed archive·Production 패키지도 별도로 확인했다.
- iPhone: 생성 두 유형·빈 초안, 글/체크리스트 재실행, 이전 필기 읽기 전용·재실행·복합 수정 보존, 저장 실패 복구, 큰 글자, 빈 상태·검색 복구의 7개 검사 통과. 최종 소스에서 저장·완료·정렬·고정·검색·삭제·재실행 흐름을 다시 통과했다.
- iPad: 회전 중 저장 실패 초안 보존과 빈 상태·검색 복구 통과. 최종 소스에서 복합 메모 글 수정 → 체크 항목 추가·입력·완료 → 열 접기/펼치기 → 이전 필기 보기 → 재열기·기존 내용 보존 검사를 통과했다.
- iPad 편집기의 Lazy 행이 삽입·포커스 전환과 함께 사라지는 현상은 일반 VStack과 설치 후 포커스 적용으로 해소했다. 초기 결과 수집 지연은 실행을 종료한 뒤 상세 진단 수집을 끄고 재검증했다.
- macOS는 Debug·Release 빌드와 코드 검토까지 확인했다. 실제 macOS 창 조작 검증은 수행하지 않았다.
- 화면과 로그는 `.local/memo-text-checklist-20261127/`에 보관한다. `.local/backups/`는 사용하거나 수정하지 않았다.

기존 세 유형 생성 설계의 이력은 [메모 생성 유형 분리](MEMO_TYPE_CREATION_PLAN.md)에 보존한다.

후속 TestFlight 배포는 [build 96 기록](../../releases/TESTFLIGHT_BUILD_96.md)을 따른다. 서명·패키지 검증과 iOS·macOS 업로드를 완료했으며, 계약 오류 해결 후 양 플랫폼의 Apple 패키지 수락·처리 시작과 TestFlight 처리 중 상태를 확인했다.
